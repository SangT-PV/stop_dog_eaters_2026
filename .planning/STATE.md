### Unplanned hotfix — 2026-07-28

**Why it was unplanned:** the daily automation had been failing silently since
2026-07-01 and nobody was alerted; `run.log` recorded only `Stage 1 failed with
code 1`, 27 times. Discovered while onboarding, not from a roadmap item.

**Root causes found (all verified, not inferred):**
1. `.env` pinned `AWS_PROFILE=dev-us-aws-bedrock` — a profile deleted 2026-06.
   Every Bedrock call returned 403 "security token is invalid". Last successful
   post: 6c960a1, 2026-06-30.
2. The Vertex/Imagen banner path died 2026-05-31 from **interpreter drift**:
   `python` resolves to `AppData/Local/hermes/hermes-agent/venv` (3.11) while
   `pip` targets a WindowsApps 3.13. `google-cloud-aiplatform` was installed into
   3.13, invisible to the pipeline. The venv was created 2026-06-07. An unguarded
   `import vertexai` raised ImportError past the provider fallback chain and was
   swallowed as a WARNING, so no log ever showed the cause.
3. Google generative AI is **denied** for `stop.dog.eaters.sde@gmail.com` /
   `sde-vertex-project` — 403 even for plain text. Not fixable in code.
4. `run.bat` never staged `website/assets/banners/`, so 28 posts referenced hero
   images that 404'd in production.
5. Two stat-extraction bugs shipped to live banners: `0 REGISTERED VIETNAMESE
   DONG` (bare-zero regex matching "150,000") and the timeline `2030 2023 2026`
   (unordered set, future year as history).

**Resolution:** AWS profile → `struong-aws-bedrock` (us-east-2, user's explicit
billing decision). Banners now come from the new `gpt-image-banner` skill in
HYBRID mode — `gpt-image-2` on Azure renders illustration only with no text, and
the skill overlays headline + statistics as SVG read from the post JSON, so
figures cannot be garbled. The prior Imagen banner shipped with "Unregalalted"
in its headline; that class of failure is now structurally impossible.

**Verified:** two full `pipeline.py` runs at exit 0 with Bedrock HTTP 200; skill
evals 9/9; `test_banner_stats.py` 5/5; banner visually inspected in-browser.

**Deployment defect found after the above (2026-07-28):** the Vercel project had **no git
connection at all** — it was created by a one-off CLI deploy on 2026-06-16 and never wired up,
so `run.bat`'s "Push to GitHub to deploy" comment had been wrong for 6 weeks and 14 posts
(06-16 → 06-30) reached GitHub but never the live site. Under the previous Cloudflare Pages
host, push-to-deploy was automatic; the Vercel migration silently dropped it.

Now fixed and verified: Vercel git-connected to **`SangT-PV/stop_dog_eaters_2026` (private)**,
production branch **`master`** (Vercel defaults to `main` — a mismatch builds Preview, not
production), root directory **`website`**. A `private` remote was added and `run.bat` Stage 3
now pushes to both `private` (deploy source) and `origin` (team copy). Live site verified
serving 93 posts, latest 2026-07-28, post JSON + banner both HTTP 200.
