**B. Create `website/js/moderation.js`**:

Class-based module with password-gated initialization:

1. **Password protection** (Claude's discretion: simple JavaScript check):
   - Password stored as SHA-256 hash in the code (not plaintext). Default password: `sde-moderate-2026` (can be changed).
   - Hash computed at page load using `crypto.subtle.digest('SHA-256', ...)`.
   - On correct password: hide gate, show dashboard, store `sde-mod-auth` in `sessionStorage` (persists only for browser session).
   - On page load: check `sessionStorage` for existing auth token. If present, skip password prompt.
   - This is a deterrent, not real security. The data is in JSON files visible to anyone. This just prevents casual access to the moderation UI.

2. **`class ModerationDashboard`**:

   **`async init()`**:
   - Load pending comments from `localStorage` key `sde-pending-comments`.
   - Load pending community posts from `localStorage` key `sde-pending-community-posts`.
   - Render both lists.
   - Set up tab switching and event delegation.

   **`renderCommentQueue(comments)`**:
   For each pending comment, display:
   ```html
   <div class="mod-item" data-id="{id}" data-type="comment">
     <div class="mod-item-header">
       <div class="mod-item-meta">
         <strong>{author_name}</strong>
         <span class="mod-item-email">{author_email}</span>
         <span class="mod-item-date">{created_at formatted}</span>
       </div>
       <span class="mod-item-context">On: {post_slug}</span>
       {if parent_id:}<span class="mod-item-reply">Reply to comment</span>{endif}
     </div>
     <div class="mod-item-content">{content with escapeHTML}</div>
     <div class="mod-item-actions">
       <button class="btn btn-primary btn-sm mod-approve" data-id="{id}">Approve</button>
       <button class="btn btn-outline btn-sm mod-reject" data-id="{id}">Reject</button>
     </div>
   </div>
   ```
   Empty state: "No pending comments to review."

   **`renderPostQueue(posts)`**: Similar layout for community post submissions, showing title + content preview + tag. Empty state: "No pending community posts to review."

   **`async approveComment(commentId)`**:
   - Find the comment in the pending array (from localStorage `sde-pending-comments`).
   - Update its `status` to `'approved'`, set `moderated_at` to `new Date().toISOString()`, set `moderated_by` to `'Tuan Anh'`.
   - **Critical persistence logic for static site**: Since there is no backend API, approved comments need to be stored somewhere accessible. Approach:
     a. Move the comment from `sde-pending-comments` to `sde-approved-comments` in localStorage.
     b. Also store in a per-post key: `sde-comments-{post_slug}` (array of approved comments for that post).
     c. The `comments.js` module (Plan 01/03) should read both `data/comments/{slug}-comments.json` AND `localStorage` key `sde-comments-{post_slug}` to display all approved comments.
     d. For production: document that periodically the admin should export approved comments to JSON files (add an "Export to JSON" button that generates downloadable JSON).
   - Remove from pending queue in UI with a brief green flash animation.
   - Update pending count badge.

   **`async rejectComment(commentId)`**:
   - Remove from `sde-pending-comments` localStorage.
   - Remove from UI with brief red flash.
   - Update count.

   **`exportCommentsToJSON()`**: Generates a downloadable JSON file from `sde-approved-comments` grouped by post_slug. Format matches `{post-slug}-comments.json` schema. Uses `URL.createObjectURL()` + `<a download>` pattern. This allows Tuan Anh to download the file and commit it to the repo.

   **Tab switching**: Click handlers on `.mod-tab` buttons to show/hide tab content.

3. **Auto-initialize** on DOMContentLoaded.
