**A. Extend `website/js/comments.js`** with submission functionality:

Add the following methods to the `CommentSection` class:

1. **`renderCommentForm(parentId = null)`**: Returns HTML string for the comment form. When `parentId` is null, it's the main form at the top. When parentId is set, it's an inline reply form.

   Form structure (per D-03 name+email auth, D-08 formatting toolbar):
   ```html
   <form class="comment-form" data-parent-id="{parentId || ''}">
     <div class="comment-form-header">
       <input type="text" class="comment-input" name="author_name" placeholder="Your name" required maxlength="100" />
       <input type="email" class="comment-input" name="author_email" placeholder="Your email (not displayed)" required />
     </div>
     <div class="comment-editor">
       <div class="comment-toolbar">
         <button type="button" class="toolbar-btn" data-format="bold" title="Bold"><strong>B</strong></button>
         <button type="button" class="toolbar-btn" data-format="italic" title="Italic"><em>I</em></button>
         <button type="button" class="toolbar-btn" data-format="underline" title="Underline"><u>U</u></button>
         <button type="button" class="toolbar-btn toolbar-emoji" data-format="emoji" title="Emoji">&#128578;</button>
       </div>
       <textarea class="comment-textarea" name="content" placeholder="Share your thoughts..." required maxlength="2000" rows="4"></textarea>
     </div>

         <button type="submit" class="btn btn-primary btn-sm">
           {parentId ? 'Post Reply' : 'Post Comment'}
         </button>
       </div>
     </div>
     <div class="comment-form-notice">
       <small>Comments are reviewed before appearing publicly. Your email is never displayed.</small>
     </div>
   </form>
   ```

2. **`handleFormatting(textarea, format)`**: For the formatting toolbar (per D-08):
   - `bold`: Wraps selected text in `**` markers (stored as plain text, rendered with markdown)
   - `italic`: Wraps selected text in `*` markers
   - `underline`: Wraps selected text in `__` markers
   - `emoji`: Opens a small emoji picker with 12 common emojis: heart, thumbsup, fire, clap, pray, cry, angry, thinking, checkmark, star, sparkles, wave. Clicking inserts at cursor position.

   The formatting markers are stored in the plain text content. The `renderCommentContent(text)` method (add this) converts `**text**` to `<strong>`, `*text*` to `<em>`, `__text__` to `<u>`, then escapes the rest.

3. **`renderCommentContent(text)`**: Parse simple markdown in content:
   - `**text**` -> `<strong>text</strong>`
   - `*text*` -> `<em>text</em>` (not inside **)
   - `__text__` -> `<u>text</u>`
   - Newlines -> `<br>`
   - Everything else: escapeHTML first, THEN apply formatting patterns
   - Order: escapeHTML -> newlines -> bold -> italic -> underline

4. **`async submitComment(form)`**: Handle form submission:
   - Extract name, email, content from form.
   - Validate: name non-empty (1-100 chars), email matches `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`, content non-empty (1-2000 chars).
   - Generate UUID: `crypto.randomUUID()` (fallback: Math.random-based for older browsers).
   - Build comment object per _schema.json: `{ id, post_slug: this.postSlug, parent_id: form.dataset.parentId || null, author_name, author_email, content, likes: 0, status: 'pending', created_at: new Date().toISOString(), moderated_at: null, moderated_by: null }`.
   - **Storage**: Since this is a static site with JSON files, comments cannot be truly persisted via frontend alone. Implement a two-part approach:
     a. Store the comment in `localStorage` under key `sde-pending-comments` (array of comment objects). This allows the moderation dashboard to pick them up.
     b. Show a success message: "Thank you! Your comment is being reviewed and will appear once approved."
     c. Optimistically add the comment to the displayed list with a "pending review" badge so the user sees their submission.
   - Clear the form after successful submission.
   - If it's a reply form, remove the inline reply form after submission.

5. **`handleLike(commentId)`**: Like button handler:
   - Track liked comments in `localStorage` under key `sde-liked-comments` (Set of IDs).
   - If not already liked: increment the displayed count, add to localStorage set, add `.liked` class to button.
   - If already liked: decrement, remove from set, remove class.
   - Since we can't persist to JSON from frontend, likes are local-only for MVP.

6. **`handleReplyClick(commentId)`**: Reply button handler:
   - Remove any existing inline reply form (only one active at a time).
   - Insert reply form HTML below the clicked comment's `.comment-card` div (inside the `.comment-replies` wrapper).
   - Focus the name input.

7. **Event delegation**: Add a single click handler on `#comments-container` for:
   - `.comment-like-btn` clicks -> `handleLike()`
   - `.comment-reply-btn` clicks -> `handleReplyClick()`
   - `.comment-cancel-reply` clicks -> remove inline reply form
   - `.toolbar-btn` clicks -> `handleFormatting()`
   - Form `submit` events -> `submitComment()`
   - Textarea `input` events -> update character count

**B. Update the `renderComments()` method** (from Plan 01) to:
   - Use `renderCommentContent()` instead of plain escapeHTML for comment body text.
   - Add the main comment form at the top of the comments section (before the comment list).
   - Render comments with the "pending review" badge for locally-stored pending comments.
