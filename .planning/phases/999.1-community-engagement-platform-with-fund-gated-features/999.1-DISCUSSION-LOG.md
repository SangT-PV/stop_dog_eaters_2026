## Storage & Authentication

### Question 1: How should comments and community posts be stored?

| Option | Description | Selected |
|--------|-------------|----------|
| JSON files | Match existing blog pattern (data/posts/). Simple, no database needed. Works for MVP scale (<1000 comments). Easy to deploy on Cloudflare Pages. | ✓ |
| Database (PostgreSQL/Supabase) | Better for scale and queries. Requires hosting setup. Supabase offers free tier + auth built-in. | |
| Hybrid (JSON + future DB) | Start with JSON files, plan migration path to database when scale requires it. | |

**User's choice:** JSON files (Recommended)

### Question 2: How should users authenticate to post comments and content?

| Option | Description | Selected |
|--------|-------------|----------|
| Name + Email only | Simplest. No accounts, no passwords. Email validation only. Matches petition form pattern. Risk: spoofing, but moderation catches abuse. | ✓ |
| Third-party auth (Google/Facebook) | OAuth 2.0. Verified identities, no password management. Requires library (e.g., Auth0, Supabase Auth). More setup but reduces spam. | |
| Email magic links | Passwordless. Email a login link. Middle ground: verifies email ownership without passwords. Requires backend to generate/verify tokens. | |

**User's choice:** Name + Email only (Recommended)

### Question 3: Where should comment JSON files be stored?

| Option | Description | Selected |
|--------|-------------|----------|
| website/data/comments/ | Parallel to posts/. One file per blog post: {post-slug}-comments.json. Clean separation, easy to find. | ✓ |
| Nested in posts data | website/data/posts/{slug}.json includes comments array. Single file per post. Simple but larger files. | |
| Separate comments/ root directory | Top-level comments/ next to website/. Clearer separation if comments become complex. | |

**User's choice:** website/data/comments/ (Recommended)

### Question 4: How should approved community posts integrate with AI-generated blog posts?

| Option | Description | Selected |
|--------|-------------|----------|
| Same data structure | Approved community posts go into data/posts/ with author:'Community' tag. Shows in same blog feed. Simple - reuses existing blog.html rendering. | ✓ |
| Separate community section | New data/community-posts/ and community.html page. Keeps AI and community content separate. Requires new page + routing. | |
| Tagged but filtered | Same data/posts/ but with type:'community' field. blog.html can filter/toggle between AI and community posts. | |

**User's choice:** Same data structure (Recommended)

## AI Bot Behavior

### Question 1: When should the AI bot respond to comments?

| Option | Description | Selected |
|--------|-------------|----------|
| Selective (keyword/sentiment-based) | Bot responds only to comments with questions, keywords (e.g., 'rabies', 'regulation'), or negative sentiment. Avoids spam. More thoughtful. | ✓ |
| All comments | Bot responds to every comment. Keeps conversation active but may feel overwhelming or spammy. | |
| Manual trigger by moderator | Tuan Anh decides which comments get bot responses. Most control but requires manual work. | |

**User's choice:** Selective (keyword/sentiment-based) (Recommended)

### Question 2: Which AI model should power the engagement bot?

| Option | Description | Selected |
|--------|-------------|----------|
| Claude Haiku | Already integrated for blog generation. Fast, cost-effective ($0.25/million tokens). Consistent with existing automation/claude_client.py. | ✓ |
| GPT-4 Turbo | OpenAI alternative. Similar quality. Requires new API integration. ~$10/million tokens. | |
| Reuse Claude Sonnet | Same model as blog generator (if Phase 5 switches back). Higher quality but slower and more expensive than Haiku. | |

**User's choice:** Claude Haiku (Recommended)

### Question 3: How should the bot rate limit responses to avoid spam?

| Option | Description | Selected |
|--------|-------------|----------|
| 1 response per comment thread | Bot responds once to a top-level comment. No follow-ups. Simple, prevents bot conversations. | |
| Max 3 responses per post | Bot can respond to multiple comment threads but max 3 per blog post. Balanced engagement. | ✓ |
| Time-based: 1 response per hour | Bot can respond once per hour regardless of post. Very conservative. | |

**User's choice:** Max 3 responses per post

### Question 4: How should the bot maintain brand voice consistency?
